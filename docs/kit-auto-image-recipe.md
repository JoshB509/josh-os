# Kit auto-inserting image recipe: implemented, inactive

The host now has a concrete Kit control recipe in `studio/kit_auto_image.py`.
It is not registered as the active server adapter and grants Laia no general
Chrome, Read, shell, form, send, schedule or takeover capability. No restart was
performed. The ordinary worker's extra-control admission remains false.

The receipt-driven order uses the owner-verified editor controls: focus the exact
anchor, End/ArrowDown into a positively observed empty paragraph, observed plus,
unique nested inner Image button, scoped Media Gallery Choose File, caption off,
Accessibility, exact approved alt, then Saved and reload. There is no separate
insert click after file upload: Kit auto-inserts. A new `media_gallery_auto`
approval method explicitly names the combined `upload_insert` phase, so old
two-phase approvals do not silently acquire different behavior.

Each mutation remains bound to the approved source revision, original PNG hash,
existing owned broadcast, anchor and alt. Controls are exact one-use host permits.
All other body nodes, links, metadata/audience, previous images, template and footer
must remain unchanged. Pending image dimensions come from the original PNG header.
Caption/alt changes stop if the selected resource, dimensions, empty link field,
private-draft state or original source changes. Unknown upload outcomes cannot be
retried. The final service still requires independent saved/reloaded verification.

## Evidence and limitations

The supported read-only `get_broadcast` call returned the real clean image schema:
`type`, `fullWidth`, `src`, `showCaption`, `alt`. The parser accepts that exact
unlinked schema and observed `embed.filekitcdn.com/e/<account>/<resource>/email`
source form. New/unknown fields, linked/full-width images, captions on in final
readback, or different hosts need separate review. No hidden media API is used.

The local state fixture exercises eight uploads, automatic insertion, caption
switch, exact full alt, Saved/reload and matching order through the production
worker's immutable call hooks. Negative cases include locks, completed/scheduled
state, body changes, duplicate images, wrong dimensions, image links and uncertain
upload. This is **mocked local UI evidence, not a live Kit end-to-end test**. The
earlier supported CLI localhost upload tests establish file transport separately.

The production observer is still missing: it must provide fresh same-tab scoped
editor/control receipts plus positively verified selected-image source, natural
dimensions/load state, empty image-link field, full alt, caption state, Saved and
reload evidence. Current read_page alone truncates accessible names and does not
establish all those facts. No new DOM extraction or broader JavaScript permission
was enabled to fill that gap. No agent may supply these observations itself.

Activation requires that supported observer, exact-control schema verification in
the actual installed Chrome transport, owner-review exposure of the distinct
auto-insert method, and one explicitly authorized **separate private unsent test
broadcast** for end-to-end verification. Do not create that fixture without
authorization. Only after that verification should an owner-approved deployment
bind this recipe as the active adapter. Manual-broadcast adoption remains a
separate guarded intake and has not been added.
